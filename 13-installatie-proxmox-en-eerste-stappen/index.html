13 Installatie Proxmox en eerste stappen¶

13.1 Doelstellingen¶

Na dit hoofdstuk beheerst de student het volgende:

  • het verschil uitleggen tussen een hypervisor van type 1 en type 2, met voorbeelden van allebei;

  • de belangrijkste eigenschappen van Proxmox VE benoemen en vergelijken met ESXi en Hyper-V;

  • uitleggen wat hyperconverged infrastructure is en welke rol Ceph daarin speelt;

  • het verschil uitleggen tussen de community- en de enterprise-repository, en het licentiemodel van Proxmox;

  • de lagen van de Proxmox-architectuur herkennen: kernel, QEMU, virtuele machines en containers, diensten en beheertools;

  • uitleggen wat een Proxmox-cluster is, en wat quorum en split-brain betekenen;

  • in VMware Workstation een virtuele machine aanmaken die geschikt is om Proxmox VE in te installeren;

  • Proxmox VE installeren en aanmelden op de webinterface;

  • de onderdelen van die webinterface benoemen: datacenter, node, takenlogboek en bedieningsknoppen;

  • de server bereiken via de webinterface en via de commandoregel, en de sterke punten van allebei benoemen;

  • de repositories omzetten naar de gratis no-subscription-variant en het systeem bijwerken;

  • de abonnementswaarschuwing uitzetten;

  • de bestanden in /etc/apt/sources.list.d/ lezen en aangeven welke regel een repository in- of uitschakelt;

  • de repositories op drie manieren aanpassen: met het post-install-script, rechtstreeks in de tekstbestanden en via de webinterface.

13.2 Inleiding¶

13.2.1 Hypervisors¶

Een hypervisor van type 1 draait rechtstreeks op de hardware en beheert zelf het geheugen, de processor en de andere bronnen. Een hypervisor van type 2 draait als programma bovenop een besturingssysteem en spreekt die bronnen aan via dat besturingssysteem.

Voorbeelden:

  • Type 2
    VMware Workstation en Virtualbox

  • Type 1
    VMware ESXi, Microsoft Hyper-V en Proxmox

Proxmox VE, VMware ESXi en Hyper-V hebben verschillende gemeenschappelijke functies, die essentieel zijn voor virtualisatieplatformen:

  • Virtualisatie van besturingssystemen
    Alle drie ondersteunen het draaien van meerdere virtuele machines (VM's) op één fysieke server, waardoor hardware efficiënter wordt gebruikt.

  • Live migratie
    Ze bieden mogelijkheden om VM's live te migreren tussen hosts zonder downtime.

  • Snapshot-functionaliteit
    Ondersteuning voor het maken van snapshots van VM's, zodat snel teruggedraaid kan worden naar een vorige toestand.

  • Clustering
    Mogelijkheid om meerdere hosts te groeperen voor schaalbaarheid en failover-functionaliteit.

  • Beheerinterface
    Alle drie bieden beheer via een GUI (web- of applicatiegebaseerd) en command-line tools.

  • Netwerkvirtualisatie
    Ondersteuning voor virtuele netwerken, VLAN's en geavanceerde netwerkconfiguraties.

  • Opslagopties
    Ondersteuning voor verschillende opslagmethoden, zoals NFS, iSCSI en lokale opslag.

  • Ondersteuning van diverse besturingssystemen
    Ze kunnen een breed scala aan gast-besturingssystemen draaien, waaronder Linux, Windows en BSD.

  • Integratie met externe tools: Alle drie kunnen worden geïntegreerd met back-up-, monitoring- en beheertools.

13.3 Hypervisor Proxmox¶

Proxmox Virtual Environment (kortweg Proxmox VE) is een open source virtualisatieplatform, sinds 2008 ontwikkeld door het Oostenrijkse Proxmox Server Solutions en vrijgegeven onder de GNU AGPL licentie. Het ondersteunt zowel VM's (virtuele machines) op basis van KVM (Linux Kernel-based Virtual Machine) alsook containers op basis van Linux Container LXC. Hun inkomsten genereren ze voornamelijk via betaalde ondersteuningsabonnementen. Deze abonnementen bieden toegang tot de Proxmox Enterprise Repository, die stabiele en geteste updates bevat, evenals technische ondersteuning op verschillende niveaus.

13.3.1 Nodes en clusters¶

Een enkele Proxmox-server heet een node. Zo'n node kan perfect alleen werken: dat is een standalone server, en daar beginnen we mee. Zet je meerdere nodes samen, dan vormen ze een cluster: een groep servers die je als een geheel beheert.

Een cluster levert het volgende op:

  • de configuratie is gedeeld: alle nodes hebben dezelfde bestanden onder /etc/pve, dus een wijziging op een node staat meteen op de andere;

  • je meldt je aan op gelijk welke node en beheert van daaruit de hele groep;

  • pas in een cluster kan je een virtuele machine live naar een andere server verplaatsen, of ze automatisch laten herstarten wanneer een server uitvalt.

Die twee laatste mogelijkheden hebben een naam. Bij live migratie verhuis je zelf een draaiende virtuele machine naar een andere node, bijvoorbeeld omdat je de eerste wil bijwerken.

High availability werkt zonder dat je iets doet. Valt een node onverwacht uit, dan starten de overblijvende nodes haar virtuele machines opnieuw op.

De nodes moeten het onderling eens zijn over wie er nog meedoet. Daarvoor is een meerderheid nodig: het quorum. Meer dan de helft van de nodes moet bereikbaar zijn voor het cluster nog iets mag beslissen.

Valt die meerderheid weg, dan zet Proxmox /etc/pve op alleen-lezen. Virtuele machines die al draaien, blijven gewoon doorlopen, maar je kan er niets meer aan wijzigen en er komt er geen bij. Met twee nodes gebeurt dat al zodra er een uitvalt; met drie nodes niet. Daarom werk je in de praktijk met minstens drie servers.

Die regel bestaat om split-brain te voorkomen. Stel dat de verbinding tussen de nodes wegvalt terwijl alle servers blijven draaien. Elke helft ziet de andere niet meer en zou kunnen besluiten dat zij nog als enige over is. Zonder quorum zouden beide helften dezelfde virtuele machine starten, allebei schrijvend naar dezelfde gedeelde opslag. Het bestandssysteem van die machine is dan onherstelbaar beschadigd. Door een meerderheid te eisen kan hoogstens een helft handelen: de andere legt zichzelf stil.

Wij werken voorlopig met een enkele node. Hoe je een cluster opzet en beheert, bekijken we later.

13.3.2 Hardwarevereisten¶

Proxmox VE draait op 64-bit processors van Intel of AMD met ondersteuning voor Intel VT of AMD-V. Je hebt minstens 4 GB RAM en 32 GB opslag nodig.

Wij installeren Proxmox VE in VMware Workstation.

In een testopstelling volstaat een eenvoudige NUC; in productie gebruik je serverhardware. Wordt de hardware door Debian ondersteund, dan werkt Proxmox VE erop.

13.3.3 Hyperconverged Infrastructure (HCI)¶

Hyperconverged infrastructure is geen nieuw idee, maar het wint de laatste jaren sterk aan terrein bij kmo's, vooral omwille van de kostprijs. Een klassieke omgeving met hoge beschikbaarheid bestaat bijvoorbeeld uit drie servers voor de rekenkracht en drie servers voor de centrale opslag, samen zes machines. Bij HCI vallen die twee samen: de opslag draait op dezelfde servers als de virtuele machines.

Binnen Proxmox VE doe je dat met Ceph. Zo zet je een cluster van meerdere nodes op met gedeelde opslag die over diezelfde nodes verspreid zit.

13.3.4 Licenties en het verdienmodel¶

Proxmox VE is vrijgegeven onder de open source licentie GNU AGPL v3 en is gratis te downloaden en te gebruiken.

Proxmox VE gebruikt Debian als besturingssysteem. Na de installatie staat de gratis community-repository klaar; tegen betaling krijg je toegang tot de enterprise-repository.

Het verschil tussen beide is tweeledig. De updates verschijnen eerst in de community-repository en pas enkele weken later in de enterprise-repository, zodat die laatste beter uitgetest is. Daarnaast bevatten sommige enterprise-abonnementen ook ondersteuning.

Qua functionaliteit zijn ze identiek. De enterprise-variant bevat niets extra; ze loopt alleen enkele weken achter.

In een professionele omgeving kies je voor de enterprise-repository, puur omwille van de stabiliteit. Alle nodes van een cluster moeten dezelfde licentie hebben; mengen kan niet.

De enterprise-licentie betaal je per bezette processorsocket, niet per core. Of in die socket nu een Intel i3 met zes cores zit of een AMD EPYC met achtenveertig, de prijs blijft dezelfde. Er bestaan maar vier licentiemodellen, dus veel uitzoekwerk is er niet.

Meer info: https://www.proxmox.com/en/proxmox-virtual-environment/pricing.

13.3.5 Beheer¶

Voor het beheer van Proxmox VE heb je geen extra software of beheerserver nodig. Elke installatie bevat alles, en je kiest zelf hoe je werkt:

  • de webinterface: je surft naar https://<ip-adres>:8006 en beheert daar de node en, als je er een hebt, het volledige cluster. Je moet niets installeren, een browser volstaat;

  • de commandoregel: je meldt je aan via SSH of via de shell in de webinterface. Alles wat je kan aanklikken, kan je ook typen, en je kan het in scripts gieten;

  • de REST-API: dezelfde opdrachten vanuit andere software, bijvoorbeeld om virtuele machines automatisch uit te rollen.

Je kan die drie door elkaar gebruiken, want ze spreken dezelfde diensten aan. Verderop in dit hoofdstuk werk je zowel met de webinterface als met de commandoregel.

Upgraden is daardoor eenvoudig. Elke upgrade komt met duidelijke instructies, en meestal volstaat de webinterface. Heb je een cluster, dan blijven de virtuele machines ondertussen draaien dankzij live migratie. Ook de sprong naar een nieuwe Debian-versie verloopt vlot.

13.3.6 Backups en snapshots¶

Van elke virtuele machine kan je snapshots nemen. Proxmox VE heeft ook een ingebouwde back-upoplossing, bijvoorbeeld voor een dagelijkse back-up van je machines en containers. Wil je meer mogelijkheden, dan is Proxmox Backup Server het bekijken waard: die installeer je op een aparte server en gebruik je als centrale back-upoplossing.

Die twee lijken op elkaar, maar ze dienen een ander doel.

13.3.7 Beveiliging¶

De nodes van een cluster communiceren onderling via SSH. Proxmox VE heeft een ingebouwde firewall op drie niveaus: cluster, host en virtuele machine. Op elk niveau stel je eigen regels in, voor IPv4 en IPv6. Aanmelden op de webinterface kan ook met tweestapsverificatie, bijvoorbeeld met een YubiKey.

13.3.8 Architectuur Proxmox¶

Het diagram hierboven toont hoe Proxmox VE is opgebouwd. Van onder naar boven:

  • Linux-kernel: KVM voor volledige virtuele machines, LXC voor containers, en AppArmor en cgroups om alles af te schermen en de resources te verdelen. AppArmor speelt in Debian dezelfde rol als SELinux in Red Hat.

  • QEMU: voert de virtuele machines uit en bootst de hardware na die een gastbesturingssysteem te zien krijgt.

  • Virtuele machines en containers: een VM draait een eigen besturingssysteem, een container deelt de kernel van de host en is dus lichter. Let op: dit zijn LXC-containers, geen Docker- of Podman-containers.

  • Diensten: de programma's die op elke node op de achtergrond draaien, ook op een standalone server.

    • pveproxy: bedient de webinterface en de API op poort 8006. De naam zegt wat hij doet: het is een tussenstation, een proxy. Hij neemt je verzoek aan en geeft het door aan pvedaemon, of aan een andere node als de virtuele machine daar staat. Zelf voert hij niets uit.

    • pvedaemon: voert de opdrachten uit, met rootrechten. Virtuele machines en containers starten, stoppen en aanmaken gebeurt hier.

    • pvestatd: verzamelt om de paar seconden de toestand van de virtuele machines, de containers en de opslag. Daar komen de grafieken en de statusicoontjes in de webinterface vandaan.

    • pve-cluster: houdt /etc/pve op alle nodes gelijk. Op een standalone server beheert deze dienst gewoon de configuratie van die ene node.

  • Beheertools: de commando's waarmee je hetzelfde doet zonder webinterface.

    • qm: virtuele machines beheren;

    • pct: containers beheren;

    • pvesm: opslag beheren;

    • pvecm: het cluster beheren.

Die lagen werken samen. Klik je in de webinterface op Start bij een virtuele machine, dan neemt pveproxy je verzoek aan, geeft pvedaemon de opdracht door, en start QEMU de machine met KVM in de kernel. Typ je in de plaats daarvan qm start 100 in een shell, dan kom je bij diezelfde pvedaemon uit. De webinterface is dus geen aparte wereld, maar een schil rond dezelfde diensten.

Onderstaande figuur toont de opstelling waarmee we in deze OLOD werken: een standalone Proxmox-server, zoals hierboven beschreven, die zelf in een virtuele machine draait.

13.4 Proxmox VE installeren¶

13.4.1 Download ISO¶

Om Proxmox VE te installeren, download je eerst de installatiesoftware van https://www.proxmox.com/en/downloads.

13.4.2 Aanmaken VM voor Proxmox¶

  • Open uiteraard VMware Workstation 26H1u1 op je systeem.

  • Klik op File, New Virtual Machine.

  • Kies in onderstaand venster voor Typical en klik op Next.

  • Kies in het volgende venster de gedownloade Proxmox ISO-image door te klikken op Browse en het ISO-bestand te selecteren. Klik erna op Next.

  • Stel het gastbesturingssysteem in als Linux en de versie als Debian 13.x 64-bit.

  • Geef uw virtuele machine een naam en selecteer de locatie. Klik dan Next.

  • Kies voor een schijf van 200 GB en klik op Next.
    PS De optie i.v.m. het splitten van virtuele schijven is niet belangrijk voor ons.

  • Controleer de informatie en klik erna op Customize Hardware… .

  • Pas de instellingen aan.

    • Memory: minimaal 4GB.

    • Processors: maximaliseer Total processor Cores (afhankelijk van je processor) en zet een vinkje voor Virtualize Intel VT-x/EPT or AMD-V/RVI. Klik erna op Close.

  • Klik erna op Finish.

13.5 Beheer via GUI en CLI¶

13.5.1 GUI¶

De GUI van Proxmox die je nu voor je ziet is gemakkelijk te gebruiken.

Kenmerken van de GUI:

  • Overzichtelijk dashboard: geeft statusinformatie over nodes, opslag, netwerken en resources.

  • Beheer van virtuele machines en containers: aanmaken, starten, stoppen en configureren van VM's en containers.

  • Snapshots en back-ups: eenvoudige toegang tot snapshotbeheer en back-upfuncties.

  • Netwerkconfiguratie: instellen van bridges, VLAN's en netwerkinterfaces.

  • Clusterbeheer: beheer van meerdere Proxmox-nodes binnen een cluster.

Je kan de webgebaseerde beheerinterface gebruiken met elke moderne browser. Wanneer Proxmox VE detecteert dat je verbinding maakt vanaf een mobiel apparaat, word je doorgestuurd naar een eenvoudigere interface die aangepast is voor een mobiel apparaat.

De kracht van Proxmox zit erin dat je vanuit de webinterface van gelijk welke node de volledige omgeving beheert. De belangrijkste onderdelen:

  • Datacenter als hoogste organisatieniveau

Het datacenter is de hoogste organisatorische eenheid. Van daaruit beheer je alle nodes met hun virtuele machines, containers en opslag, en krijg je een overzicht van de volledige infrastructuur.

  • Knooppunten en hun componenten

Elke node is een host in het cluster. Hier is er maar één: pve. Een node heeft zijn eigen netwerk, opslag en configuratie. Klik je een node aan, dan opent een venster waarin je dat allemaal beheert.

  • Taakbeheer en logging

Onderaan loopt een takenlogboek in realtime.

  • Gebruiksvriendelijke bedieningsknoppen

Rechtsboven staan de bedieningsknoppen voor virtuele machines en containers: starten, stoppen en migreren. Ook de console en het verdere beheer bereik je daar.

Proxmox biedt dus zowel een doordachte webinterface als volwaardige toegang via de commandoregel, en is daardoor bruikbaar voor wie net begint en voor de ervaren beheerder.

13.6 Tijd correct zetten¶

De klok van Proxmox moet juist staan. Loopt hij te ver voor of achter, dan weigert apt de pakketlijsten omdat hij de handtekeningen van de repository niet meer vertrouwt, en in een cluster raken de nodes het onderling oneens over wie er nog meedoet.

Na de installatie in een virtuele machine klopt de tijd vaak niet. Controleer ze:

root@pve:~# timedatectl

Drie regels zijn van belang:

  • Local time is de tijd die de server zelf hanteert;

  • System clock synchronized zegt of die tijd van een tijdserver komt. Staat daar no, dan loopt de klok vrij;

  • NTP service zegt of de tijddienst draait.

Staat er bij System clock synchronized no, dan haalt de server zijn tijd niet op. Herstart dan de tijddienst:

root@pve:~# systemctl restart chronyd

Vraag de tijd daarna opnieuw op. Staat System clock synchronized nog altijd op no, of wijkt Local time nog zichtbaar af van de werkelijke tijd, dan dwing je de correctie in één keer af:

root@pve:~# chronyc makestep

Vraag de tijd opnieuw op (wacht wel eventjes).

root@pve:~# timedatectl

Let op: ook nadat je een snapshot hebt teruggezet, staat de klok vaak verkeerd. Dezelfde herstart lost dat op.

13.7 Repositories aanpassen¶

Je kan de repositories op drie manieren aanpassen. We bekijken ze alle drie, en ze doen alle drie precies hetzelfde.

13.7.1 Via het script¶

We maken verbinding via SSH om de repositories aan te passen.

C:\Users\stijn>ssh root@192.168.112.144

Voer het onderstaande uit.

We gebruiken dist-upgrade en niet gewoon upgrade. Met upgrade slaat apt elk pakket over waarvoor iets extra geïnstalleerd of verwijderd moet worden, en bij Proxmox is dat net het geval zodra er een nieuwe kernel klaarstaat. Met dist-upgrade lost apt die afhankelijkheden wel op.

root@pve:~# apt-get update && apt-get dist-upgrade

Je krijgt foutmeldingen. Dat komt doordat Proxmox er na de installatie van uitgaat dat je een betalend abonnement hebt: zonder abonnement krijg je geen toegang tot de repository die de foutmelding geeft.

De gratis repositories mag je wel gebruiken, en dat is volkomen legaal.

Je kan dit manueel aanpassen maar voor gratis gebruik maak je meestal gebruik van een  PVE Post Install-script dat je vindt op https://community-scripts.org/scripts/post-pve-install.

root@pve:~# bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/tools/pve/post-pve-install.sh)"

Klik in het venster erna op OK.

De pve-enterprise waarvoor je moet betalen zetten we op disable.

De ceph enterprise repository disablen we ook.

We staan nu verbinding toe met pve-no-subscription. Dat zijn de gratis, open-source componenten.

We voegen ook de Ceph Package Repositories toe.

De pve-test repository voegen we op dit moment niet toe.

Erna krijg je de mogelijkheid om de Abonnementswaarschuwing uit te zetten. Het gaat over deze waarschuwing die je krijgt als je in GUI inlogt:

Doe dit.

Let wel: bij een update van het pakket proxmox-widget-toolkit wordt dat bestand overschreven en komt de melding terug. Je brengt de wijziging dan opnieuw aan.

Je krijgt hier ook een melding dat het ondersteunen van het ontwikkelaarsteam essentieel is. Klik op Ok.

Erna krijg je de mogelijkheid om High Availability uit te zetten. We doen dat nu niet.

Er wordt nu gevraagd om Proxmox VE nu te updaten. We kiezen voor yes.

Je zal nu geduld moeten hebben…

Je krijgt erna nog een melding dat je dit script op alle hosts op je cluster dient uit te voeren indien je een cluster aanmaakt. Klik op OK.

Erna wordt aangeraden om Proxmox te herstarten. Doe dit.

We voeren het commando nog eens uit.

root@pve:~# apt-get update && apt-get dist-upgrade

Nu komt er geen fout meer voor.

De updates worden gewoon opgehaald en geïnstalleerd.

13.7.2 Via de commandoregel¶

Het script en ook de knoppen in de webinterface doen allebei hetzelfde: ze passen tekstbestanden aan. Sinds Proxmox VE 9, dat op Debian 13 gebouwd is, staan de repositories in afzonderlijke bestanden met de extensie .sources. Bekijk ze zelf:

root@pve:~# ls /etc/apt/sources.list.d/
ceph.sources  debian.sources  proxmox.sources  pve-enterprise.sources

We bekijken één voorbeeld hieruit.

root@pve:~# cat /etc/apt/sources.list.d/pve-enterprise.sources

Zo'n bestand bestaat uit sleutel-waardeparen, een per regel. De belangrijkste zijn:

  • Types: het soort pakketten, meestal deb;

  • URIs: het adres van de server waar de pakketten staan;

  • Suites: de versie van Debian waarvoor ze bedoeld zijn, hier trixie;

  • Components: welk deel van die repository je gebruikt, bijvoorbeeld pve-enterprise of pve-no-subscription;

  • Signed-By: de sleutel waarmee de pakketten ondertekend zijn;

  • Enabled: of de repository gebruikt wordt. Zet je die op false, dan blijft het bestand staan maar wordt de repository genegeerd.

Die laatste regel is precies wat het script doet wanneer het pve-enterprise op disable zet. Het bestand verdwijnt dus niet, en je kan de keuze altijd terugdraaien door Enabled weer op true te zetten.

Je kan dat ook gewoon zelf doen met een teksteditor. Na elke wijziging moet je de lijst opnieuw ophalen:

root@pve:~# apt-get update

Let op: verwijder de enterprise-repository niet. Een update van Proxmox kan het bestand opnieuw aanmaken, en dan krijg je weer met dezelfde foutmelding. Uitschakelen volstaat.

13.7.3 Via de webinterface¶

Dezelfde instellingen kan je ook aanpassen zonder commandoregel. Klik in de webinterface links op de node pve, en daarna op Updates en Repositories.

Je krijgt een lijst van alle repositories die op de server ingesteld staan. Per regel zie je in welk bestand ze staat, welke component ze aanbiedt en of ze actief is. Dat zijn precies de bestanden die je hierboven met cat bekeken hebt.

Daarmee kan je:

  • een repository selecteren en met Enable of Disable aan- of uitzetten. Proxmox schrijft dan dezelfde regel Enabled in hetzelfde bestand (doe onderstaande niet, is ter illustratie);

  • met Add een repository toevoegen. Je krijgt een keuzelijst met de bekende repositories, waaronder No-Subscription, zodat je geen adres hoeft in te typen;

  • bovenaan in een gekleurde balk aflezen hoe Proxmox je samenstelling beoordeelt: productieklaar, of een waarschuwing wanneer je de enterprise-repository aan hebt staan zonder abonnement.

Je hebt de repositories nu op drie manieren leren aanpassen, en alle drie schrijven ze in dezelfde bestanden:

  • met het post-install-script: het snelst, en het regelt meteen ook de abonnementswaarschuwing;

  • in de tekstbestanden: daar zie je wat er werkelijk verandert, en het werkt ook op een server zonder webinterface;

  • via de webinterface: het veiligst, want je kan niets fout typen.
